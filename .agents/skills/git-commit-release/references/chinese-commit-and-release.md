# 中文提交与发布模板

主技能只在需要时读取本文件。这里集中保存可直接套用的中文提交正文、拆分判断和发布说明格式。

## 提交类型

| 类型 | 适用场景 |
| --- | --- |
| `feat` | 新增用户或开发者可见能力 |
| `fix` | 修复错误、回归或边界行为 |
| `refactor` | 不改变外部行为的结构调整 |
| `perf` | 以性能改善为主要目的 |
| `docs` | 文档、注释或示例变更 |
| `test` | 只增加或调整测试 |
| `build` | 构建、依赖或打包变更 |
| `ci` | CI/CD 工作流和自动化变更 |
| `chore` | 其他不改变业务行为的维护 |
| `revert` | 回滚已有提交 |

## 推荐提交体

```text
<type>(<scope>): <中文主题>

背景：
- 说明问题、需求或触发原因。

变更：
- 说明实现的主要行为。
- 说明关键边界、事务、兼容性或错误处理。

影响：
- 说明受影响模块、配置、数据库、接口和运维动作。

验证：
- `go test ./...`
- `go vet ./...`
- `go build ./...`
```

验证区只填写实际执行过的命令；没有运行的命令不要保留。

## 示例：功能变更

```text
feat(system): 将初始化迁移与开发 seed 统一到启动流程

背景：
- System seed 原先在模块构造函数中执行，数据库初始化职责分散，模块创建存在隐式写入。

变更：
- 在 bootstrap 中按“迁移 -> seed -> 创建模块 -> 注册路由”的顺序初始化 System。
- 移除 System Module 对 seed 开关的依赖，保持模块构造函数只负责依赖组合。
- 仅允许 development 和 test 环境启用 seed，并补充启动和边界测试。

影响：
- 开发环境需通过 `system.seed_enabled` 显式启用示例数据初始化。
- 生产环境开启该配置会阻止应用启动。

验证：
- `go test ./...`
- `go vet ./...`
- `go build ./...`
```

## 示例：修复

```text
fix(auth): 修复刷新令牌重用后的会话吊销失败处理

背景：
- 外部会话吊销服务失败时，原流程可能提前返回成功，导致重试语义不明确。

变更：
- 保留可重试错误身份，并在持久化状态中记录未完成的吊销结果。
- 增加外部调用失败、重复请求和最终成功的测试覆盖。

影响：
- 会话吊销失败会返回明确错误，调用方可安全重试；不会记录令牌明文。

验证：
- `go test ./internal/shared/auth ./internal/core/config`
- `go test -race ./internal/shared/auth ./internal/core/config`
```

## 示例：文档或配置

```text
docs(system): 补充 seed 启动配置与发布说明

变更：
- 说明开发/测试环境的 seed 开关、启动顺序和生产限制。
- 同步接口文档中的初始化示例，移除已经删除的独立 seed 命令。

影响：
- 不改变运行时代码；开发者需要按文档配置 seed。

验证：
- `git diff --check`
```

## 提交拆分建议

- 代码和直接覆盖它的测试通常放在同一个逻辑 commit 中。
- 纯文档修订、依赖升级、格式化和业务修复通常分开。
- 迁移与必须同步的模型/服务代码可放在同一个功能 commit；独立的数据回填脚本应单独提交并说明执行顺序。
- 如果一个 commit 同时包含功能、无关重构和批量格式化，先拆分或明确说明无法安全拆分的原因。

## 发布说明模板

```markdown
# vX.Y.Z

## 概览

用一两句话说明本版本解决的问题和主要价值。

## 新增

- ...

## 修复

- ...

## 变更与兼容性

- ...

## 数据库、配置与运维

- 迁移：...
- 新增或变更配置：...
- 发布前/发布后操作：...
- 回滚注意事项：...

## 破坏性变更

- 无，或明确说明受影响调用方和迁移方式。

## 验证

- `实际执行的检查命令`

## 相关提交

- `<commit-sha>` `<中文提交主题>`
```

## tag 说明模板

```text
vX.Y.Z

本版本包含：
- 新增：...
- 修复：...
- 变更：...

兼容性与运维：
- ...

验证：
- `实际执行的检查命令`
```

正式版本优先使用 annotated tag；候选版本使用明确的 `-rc.N` 或 `-beta.N` 后缀。tag 目标 commit、版本来源和发布说明必须能相互对应。
